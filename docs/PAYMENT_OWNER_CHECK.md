# Проверка оплаты владельцем — 10.09.2026

На нидерландском сервере подготовлено:

- `PAYMENTS_ENABLED=true`, `PAYMENTS_ADMIN_ONLY=true` — создание платежей доступно только аккаунтам из `ADMIN_IDS`.
- `YOOKASSA_TEST=false` — рабочий магазин: списания настоящие. Это не песочница ЮKassa.
- `YOOKASSA_METHOD=auto` — выбор способов, разрешённых магазином, на странице ЮKassa.
- Публичный приём оплаты закрыт. Отсутствие ссылок на документы допустимо исключительно для закрытой проверки владельца; при отключении закрытого режима запуск с пустыми ссылками завершается ошибкой.
- Контакты: @tarotDay_support и .

## Активация на текущем сервере

В SSH-терминале нидерландского сервера:

```bash
cd /root/tarot_bot
venv/bin/python check_payments.py && systemctl restart tarot_bot.service
systemctl status tarot_bot.service --no-pager
```

Проверка не создаёт платежей. `missing_settings` относится к текущему режиму, `public_launch_missing_settings` отдельно показывает незаполненные настройки публичного запуска. Успешная проверка API не подтверждает все юридические и инфраструктурные условия запуска.

В боте открыть «Токены», выбрать пакет 10 токенов за 10 рублей, проверить предупреждение о настоящем списании и самостоятельно завершить оплату. Проверить начисление ровно 10 токенов, статус в «Мои платежи» и отсутствие повторного начисления после повторной проверки. Отдельно проверить скидочные пакеты 500 токенов за 349 рублей и 1000 токенов за 699 рублей. Если деньги списаны без начисления, сохранить номер заказа и проверить существующий платёж, не оплачивать повторно.

Режим администратора не отменяет правил Telegram или требований к учёту реальных расчётов и не является разрешением на публичные рублёвые продажи цифровых услуг внутри Telegram.

## Перед переносом на российский сервер

Копия базы, сделанная через Проводник во время работы бота, не считается проверенной. После проверки оплаты сделать свежую согласованную копию SQLite через Backup API либо после остановки записи. Сохранить заказы, баланс и права доступа. См. MIGRATION_RU.md.

Папку `venv` между серверами не переносить: Python-ссылки на скриншоте относятся к старому окружению. На новом сервере создать новое окружение и установить зависимости из requirements.txt. Отдельно перенести `.env`; не публиковать его и не присылать секреты в чат. Служба systemd не переносится вместе с папкой проекта.

Запускать только один экземпляр бота с этим токеном. Не отключать `PAYMENTS_ADMIN_ONLY` до подготовки документов и проверки условий публичного запуска. Основная база и резервные копии должны соответствовать фактической инфраструктуре, описанной в политике.
