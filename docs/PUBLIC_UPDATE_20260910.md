Изменения по поручению владельца:

- Синие кнопки раскладов и матрицы, зелёные кнопки пополнения, постоянная нижняя клавиатура.
- Порядок главного меню сохранён: расклады/матрица, совместимость/подписка, профиль/токены, доставка/о боте, админ-панель только администратору.
- Короткие тексты меню, баланс на главном экране, наглядная выгода подписки.
- `PAYMENTS_ADMIN_ONLY=false`: оплатить может любой пользователь. `PAYMENTS_ENABLED=true`, рабочий магазин ЮKassa.
- `PAYMENT_DOCUMENTS_IN_BOT=true`: перед оплатой доступны условия покупки и сведения об обработке данных; требуется кнопка согласия для перехода к оплате. Внешние ссылки остаются незаполненными. Подробные юридические документы остаются проектами.
- `RESET_NON_ADMIN_TOKENS_ONCE=public-release-20260910-v1`: после проверки конфигурации и подготовки базы, до запуска polling выполняется одноразовое обнуление всех балансов, кроме ADMIN_IDS. Это не сбрасывает подписки или купленные материалы. Каждый ненулевой баланс получает компенсирующую запись в журнале. Отрицательный баланс также становится нулевым.

## Активация на нидерландском сервере

```bash
cd /root/tarot_bot
venv/bin/python check_payments.py && systemctl restart tarot_bot.service
systemctl status tarot_bot.service --no-pager
journalctl -u tarot_bot.service -n 40 --no-pager
```

В журнале `Owner launch action` будет результат `applied`, число изменённых пользователей и путь к резервной копии. При последующих запусках — `already_applied`: новые пополнения повторно не обнуляются. Не менять идентификатор одноразовой операции без нового поручения об обнулении.

Сброс выполняется непосредственно на Linux через SQLite-транзакцию. До изменения создаётся согласованная копия `backups/.../before-reset.sqlite` и проверяется её целостность. При ошибке записи журнала вся операция откатывается, бот не открывает приём новых обновлений до успешного запуска. Базу не изменять через Windows/SSHFS во время работы сервиса.

В боте отправить `/start`, чтобы обновилась постоянная нижняя клавиатура. Цвета могут различаться в разных темах/версиях Telegram.

## Что не означает техническое включение

Правовая подготовка публичного запуска не завершена: сервер пока в Нидерландах, локализация и перенос откладываются владельцем; подробная политика и процедуры ещё готовятся. Встроенный текст сообщает фактическое размещение, не утверждает соответствие всем требованиям РФ. Правила Telegram требуют Stars для цифровых продаж внутри ботов; использование ЮKassa по выбору владельца не отменяет этих правил. Автоматизация чеков НПД не подключена.

После проверки оплаты перед переносом сделать новую согласованную копию базы: старая копия, сделанная во время работы, не содержит последующие операции и не считается проверенной.
