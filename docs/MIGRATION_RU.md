# Перенос бота и базы в РФ

Статус: план, перенос не выполнен. Причина: владелец сообщил, что сервер с основной базой находится в Нидерландах; проект предназначен в том числе для пользователей из РФ.

## Что нужно для начала

Российская локация VPS с подтверждением места размещения у провайдера и доступ для настройки. По IP-геолокации нельзя достоверно подтвердить юридически значимое место размещения. При выборе нужно учитывать и резервное хранение. Покупки серверов и новые платные договоры не выполнялись.

## Последовательность переноса

1. Проверить выбранную российскую локацию, условия хостинга, место резервных копий и доступ к Telegram и ЮKassa. Сопоставить окружение Python и зависимости с текущим сервером.
2. Подготовить каталог проекта, виртуальное окружение, права доступа и службу на новом сервере. До окончательного переключения не запускать второй экземпляр того же бота с polling.
3. Перенести проверенные исходники. `.env` передавать отдельно защищённым способом, с ограниченными правами. Сохранить действующий токен бота, ключ ЮKassa и идентификаторы магазина; перевыпуск для самого переноса не требуется. Оплату оставить выключенной.
4. Подготовить перенос базы через SQLite Backup API либо согласованную остановку записи. Не копировать один `users.db` у работающего бота, игнорируя WAL-файл: так можно потерять последние операции.
5. Перед окончательным переключением остановить старую службу, получить согласованную актуальную копию базы и сохранить её контрольную сумму. Не создавать новую пустую рабочую базу и не использовать старую тестовую копию.
6. На копии проверить `PRAGMA integrity_check`, количество пользователей, балансы, доступ к матрицам, подписки, платежи и незавершённые возвраты. Сохранить номера заказов, ID провайдера и ключи повторных запросов.
7. Проверить с нового сервера `venv/bin/python check_payments.py`: магазин и режим должны совпасть. Команда не создаёт платежей. Отдельно проверить корректность `DB_PATH` и отсутствие второго работающего процесса.
8. Запустить одну службу на новом сервере, проверить меню, чтение профиля, ранее купленные материалы и журнал запуска. Оплату не включать только на основании успешного переноса: другие незавершённые настройки рассматриваются отдельно.
9. После подтверждённого переключения отключить автозапуск старой службы. Инвентаризировать прежние копии базы и секретов на иностранном сервере, сетевом диске и локальных компьютерах. Удаление выполнять отдельным проверяемым действием после проверки восстановления; сам этот план ничего не удаляет. Не считать старые копии разрешёнными к бессрочному хранению за рубежом.
10. Обновить политику фактическими сведениями о российском хранении, проверить применимые уведомления Роскомнадзора и порядок работы с согласиями, обращениями и резервными копиями. Затем подготовить окончательные страницы документов для Telegraph.

Перенос устраняет конкретную проблему размещения основной базы. Он не подтверждает автоматически соблюдение всех требований к обработке персональных данных и не заменяет организационные меры оператора.

Основание: часть 5 статьи 18 Федерального закона №152-ФЗ — https://www.consultant.ru/document/cons_doc_LAW_61801/cbf4e15b7c330f9372e876cdf2bc928bad7950ef/
